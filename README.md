# 判斷紀錄 Judgment Log

> 成品可以被生出來，判斷不行。

記錄學生使用 AI 時**做過的判斷**——照單全收、有推回去、否決不用、做了選擇——而不是記錄 AI 生出了什麼。

---

## 這是什麼

一個瀏覽器外掛在你跟 AI 對話的當下把往返擷取下來，寫進一個你自己擁有的資料庫。原文與時間寫進去之後**任何人都改不了**，包括你自己。你可以分類、可以決定哪幾段給老師看，老師看過會留下紀錄回到你這裡。

四種判斷由 AI 判讀，被判為「照單全收」的那幾段會請你補一句為什麼——那一句可以改，但改過幾次、第一次什麼時候寫的，資料庫自己記著。

## 幾條設計上的規矩

這些不是功能，是限制。寫在這裡是因為它們比功能更難守。

| 規矩 | 意思 |
|---|---|
| **當下決定，事後不補** | 原文與擷取時間寫入後不可修改，由資料庫的 trigger 擋，不是介面沒做 |
| **可以決定歸屬，不可以決定存在** | 你可以決定一段對話屬於哪份紀錄、給誰看，但不能讓它沒發生過 |
| **記錄完整，呈現分層** | 老師看到的是判斷的結構，原文預設不開放，要你勾才給 |
| **原文不能改，你的詮釋可以改但會留痕** | 補充說明可以重寫，次數與時間由資料庫算，前端送什麼都不算數 |
| **不做「內容相似度」判斷** | 去重只認「同一個問句」，不認「意思差不多」——會讓原文安靜消失的系統，拿去當證據沒有價值 |

## 目錄

```
index.html          整個網站（單檔，不需要打包）
sql/                Supabase 的資料庫結構，照編號依序跑
extension/          Chrome 擷取外掛
docs/               安裝指南、理念說明
```

## 架起來

### 1. Supabase

建一個專案，到 SQL Editor 把 `sql/` 裡的檔案**照編號依序**各跑一次。
每一支都可以重複執行，跑第二次不會壞。細節看 [`sql/README.md`](sql/README.md)。

### 2. 網站

`index.html` 是單一檔案，丟到任何靜態空間就會動——GitHub Pages、Cloudflare Pages、直接用瀏覽器開本機檔案都可以。

專案的 URL 與 anon key 直接寫在檔案裡（第 290 行附近的 `BUILTIN`）。換成你自己的 Supabase 專案時改那兩行。

### 3. 外掛

Chrome → `chrome://extensions` → 開啟「開發人員模式」→「載入未封裝項目」→ 選 `extension/` 資料夾。

然後到網站上發一組**匯入代碼**貼進外掛。代碼 14 天到期、隨時可以撤銷、而且**只能寫不能讀**——外掛就算被拆開，拿到的人也讀不到任何一個人的任何一段紀錄。

---

## 關於公開這份原始碼

**anon key 放在公開的原始碼裡是安全的**，它本來就設計成要出現在每個人的瀏覽器裡。真正的防線是資料庫的 Row Level Security，不是把 key 藏起來。

**service_role key 永遠不要放進來**，不管是程式碼、註解、還是範例檔。那把 key 繞過所有 RLS。

如果你 fork 這個專案並接上自己的 Supabase，請先自己驗一次 RLS：用另一個帳號登入，確認讀不到別人的任何一列。

## 已知的限制

寫在這裡是因為上台之前該自己先講，不要等人問。

- **DOM 層擷取會因為網站改版失效**，而且失效的方式通常不是「抓不到」，是**抓到錯的東西還以為自己在正常運作**。2026-09-30 就發生過一次：外掛把 claude.ai 的介面狀態字（「3 minutes ago」「Running page script」）當成 AI 的回答收了進去，241 段紀錄裡有 71 段是假的，系統跑了一個禮拜沒噴任何錯誤。正式版應該在傳輸層攔截。
- **外掛第一次在既有對話上啟用時**，會把畫面上的舊訊息一次補抓，時間戳是擷取當下而非發話當下。這種紀錄會在 `source` 欄位標明，不會假裝是即時記的。
- **`chrome.storage` 使用者改得動**，本機那一段不具防竄改性。
- **bridge 不驗證訊息來源。**
- **審計列表的擁有者刪得掉**（資料庫是你自己的）。
- **真正想作弊的人不會裝這個東西。** 這套系統服務的是願意證明自己的人，不是用來抓人的。
