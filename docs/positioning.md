# 判斷紀錄 · 定位統整

> 2026-10-07。這份是現況，不是願景。
> 每一條都標了「已驗證／未驗證」——未驗證的不要寫進簡報當事實。

---

## 一、產品定位

### 一句話

> **判斷紀錄不證明學生沒用 AI。它記下學生用 AI 時做了哪些判斷，
> 讓老師不必讀四十份對話，也看得出哪幾個人值得聊一下。**

### 實際運作

```
老師開一門課，給學生一組加入碼
      ↓
學生自己安裝外掛、自己決定交哪幾份紀錄
      ↓
系統判斷每一輪：照單全收 / 有推回去 / 否決不用 / 做了選擇
被判為「照單全收」的，要求學生補一句為什麼
      ↓
老師看到：判斷分布、使用時間分布、學生寫的說明
老師看不到：對話原文
      ↓
要看內容 → 向學生請求 → 學生決定給不給（拒絕也留痕）
```

### 三條設計原則

| 原則 | 怎麼守 |
|---|---|
| 當下決定，事後不補 | 原文與時間寫入後不可修改，資料庫 trigger 擋 |
| 可以決定歸屬，不可以決定存在 | 學生可改分類、可收回開放，但刪不掉發生過的事 |
| 記錄完整，呈現分層 | 老師預設只看結構；原文要學生逐輪開放 |

**這三條都是資料庫層擋的，不是介面沒做按鈕。** 老師直接打 API 也拿不到未開放的原文——已實測。

## 二、目標客戶

### 使用者 vs 買家是不同人

| 角色 | 是誰 | 狀態 |
|---|---|---|
| 主要使用者 | 大學老師 | 轉向後的定位 |
| 次要使用者 | 學生（必須安裝，但不是買家） | — |
| **買家** | 系所 / 教發中心 / 教學實踐計畫經費 | **未驗證** |

台灣的大學老師很少能自己刷卡買軟體報帳。「客群＝老師」實際上是
**使用者是老師、決定者是老師、掏錢的是機構**——三個不同的人。

### 真正的灘頭堡（比「老師」窄很多）

> **已經在要求學生交 AI 使用過程、而且已經被淹沒的那幾個老師。**

來源：Daniel 實地聽到老師說「不反對學生用 AI，但每次都要去分辨、去看他跟 AI 的對話」。

這筆證據的價值在於它的性質：**不是問來的**（沒被誘導）、**抱怨的是成本不是原則**（原則之爭沒解，成本之痛可以賣）、
**而且那件事正在發生**（代表已經有人在做，不是想像出來的需求）。

一般老師沒有這個痛——他們根本沒要求過程，所以沒有要讀的東西。

**這批人數得出來。** 元智大概三個？五個？那不是市場，但那是試點名單，而且不用說服他們需求存在。

## 三、競爭者

照威脅程度排，不是照知名度。

### 1. 改成課堂考試、口頭問答 ← 真正的對手

零成本、不用裝任何東西、現在就能做，而且**很多老師已經在用**。

你必須能回答：為什麼不乾脆改考試就好？

### 2. Claude Learning Mode ← 平台自己的解法

學生問問題時 AI 不直接給答案，改用蘇格拉底式反問。

**方向跟你相反：預防，不是記錄。** 老師不用看任何東西、學生不用裝任何東西、沒有隱私問題。
**預防比記錄便宜。**

可以反駁的點：只在 Claude 裡有效（學生跑去用 ChatGPT 就沒了）；而且它解決不了「老師拿不出證據」。
但這個反駁要自己講得出來。

### 3. 什麼都不做

最大的競爭者。多數老師選這個。

### 4. Turnitin Clarity / Grammarly Authorship

寫作過程回放。學校買、學校擁有、學生被動被看。已在多數大學的系統裡。

### 5. Securly AI Transparency

2025/11 推出，K-12，裝在學校配發的設備上，擷取 prompt 原文，標記的是**自傷等安全風險**不是學術誠信。
對 3,000 所用其 filter 的學校**免費**。

### 6. Kritik VisibleAI

### 平台現況（已查證，2026-10）

| | 老師看得到學生的對話嗎 |
|---|---|
| ChatGPT Edu | **不行。** 管理者只有使用量層級的資料，拿不到內容 |
| Claude for Education | **沒有這個功能。** 老師端工具是出題、評分規準、寫作回饋 |

**兩大平台都明講學生對話預設私密。** 所以：

- 好消息：**你瞄準的缺口是真的，現在沒人填**
- 壞消息：**「平台把學生資料交給第三方」正是他們公開反對的事**，那種合作短期不會發生

但你的設計跟他們的立場**一致**——資料不是平台交出來的，是**學生自己交出來**的。
官方匯出功能存在的理由就是這個。

## 四、產品獨特性

三件事的組合，但**只有第一件防得住**。

### 1. 資料屬於學生 ← 唯一的結構性差異

其他全部是學校買、學校擁有、學生被動被看。

這個差異 Turnitin 和 Securly **跨不過來**，不是技術問題——付錢的是學校，
做一個「學生擁有、老師要經學生同意才看得到」的版本等於背叛客戶。
**這是商業模式的鎖，不是技術的鎖。**

### 2. 記的是判斷的種類，不是相似度分數

照單全收 / 有推回去 / 否決不用 / 做了選擇。

### 3. 當下決定，事後不補

原文與擷取時間寫入後，**任何人都改不了，包括擁有者本人**。

### 護城河（誠實版）

> **現在沒有護城河，只有時間差和立場差。**

唯一會累積的是**時間**：一個累積三年紀錄的人換不走，因為時間不能追補。
但那同時是最大的弱點——新使用者第一天打開是空的，價值要等好幾年才長出來。

被問到護城河時，這樣答比硬掰技術壁壘可信：
「護城河是使用者累積出來的，不是我做出來的。」

## 五、面臨的問題

照嚴重程度排。**這一節是整份文件最重要的部分。**

### 1. 安裝摩擦 ← 最可能致死

學生要：下載資料夾 → 開啟 Chrome 開發人員模式 → 載入未封裝項目。

**Daniel 自己是作者，裝這個東西撞了三次**（資料夾套兩層、OneDrive 中文路徑、選錯一層）。
一個 50 人的班，這個流程會攔掉多少人？

Google Classroom 能跑是因為學生拿學校帳號一點就進去。你的不是。

**解法**：上架 Chrome Web Store，變成點一下安裝。這是一條獨立的工作線，必須排進時程。

### 2. 誰付錢，未驗證

老師是使用者不是買家。從老師到機構採購是另一條路，而且沒走過。

問卷砍題時連帶砍掉了經費那兩題——**這份問卷不會回答這一題，只有訪談會。**

### 3. 桌面版做不到即時（結構限制）

外掛活在 Chrome 裡，碰不到桌面程式。桌面版只能靠官方匯出檔事後匯入。

不是「還沒做」，是辦不到。三條自動化的路都不通：
讀桌面版內部資料（脆弱、看不出壞掉）、自動呼叫匯出（沒有 API，要學生交帳密）、MCP（看不到對話本身）。

**誠實的講法**：判斷發生在當下，只有搬運是事後的。像銀行對帳單——月底才拿到，
但每一筆的時間都是當下寫的。

### 4. DOM 擷取脆弱，而且有事故紀錄

**2026-09-30**：外掛把 claude.ai 的介面狀態字（「3 minutes ago」「Running page script」）
當成 AI 的回答收進去。**241 段紀錄裡 71 段是假的，將近三成。系統跑了一個禮拜，沒噴任何錯誤。**

這件事要主動講，不要等人問。它證明的事比任何架構圖都有力：
**DOM 層擷取失效時不是「抓不到」，是「抓到錯的東西還以為自己在正常運作」。**

### 5. 你最大的賣點，對買家來說是個限制

站在老師的立場，「原文我看不到，要問學生才給」比「我全部看得到」糟。

**必須練到能脫口而出的回答**：
> 不設這個限制，學生就不會裝。學生不裝，你什麼都看不到。
> 這個限制不是在保護學生不被你看，是在讓這件事有可能發生。

### 6. 評分掛鉤會製造表演動機

一旦跟分數綁在一起，學生會故意「推回去」給系統看、把「為什麼」寫成場面話。
而真的思考和表演的思考**留下的痕跡一樣**。

目前的緩解：時間分布很難演——單一段對話可以裝，整學期穩定分散裝不出來。

### 7. 驗證資料趨近於零

- 使用者：**0**（除了 Daniel 自己）
- 問卷回收：**0**
- 老師訪談：**0**（有一次非正式交談，老師抓不到吸引力）
- 判讀品質：**沒跑過**（143 段裡 105 段還沒判讀）

## 附：被問到時的標準答覆

**「Securly / Turnitin 不是做過了？」**
> 做過了，而且免費送給三千所學校，那證明需求是真的。差別在他們的客戶是學區，所以做出來的是監控；
> 我的客戶是學生和老師，所以做的是舉證。他們永遠不會做我這一邊，因為付錢的人不希望他們做。

**「護城河是什麼？」**
> 現在沒有，只有時間差和立場差。護城河是使用者累積出來的，不是我做出來的。

**「桌面版怎麼辦？」**
> 瀏覽器即時擷取，桌面版用官方匯出檔補。桌面版做不到即時是結構限制，不是還沒做。
> 我們選擇不去挖別的程式的內部資料，因為那種做法壞掉的時候使用者看不出來——這件事我們實際踩過。

**「會不會跟 Claude 合作？」**
> 長期正確的架構是平台提供授權後的資料存取。但平台目前基於隱私立場不開放，短期也不會。
> 所以我們走「學生自己匯出」這條——它慢，但它合規，而且現在就能用。
